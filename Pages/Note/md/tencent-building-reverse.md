# 腾讯地图建筑数据抓取：从网页到带楼高的地图文件（小白详解版）

## 写在前面：这篇笔记是干什么的

想象你想做一件事：**把腾讯地图上看到的那些白色小楼块，连位置带高度一起“抄”下来**，
存成一个地图文件（GeoJSON），以后自己用。

这篇笔记就是这件事的完整手把手教程：只需要一个浏览器 + 一个免费小工具（Node.js），
跟着做就行。**不需要编程基础**，每一步都告诉你点哪里、看到什么、为什么。

> ⚠️ 先说规矩（很重要）：
> 我们用的是腾讯演示页面自带的公开钥匙，只拿来**学习、小范围试试**。
> 请每次只抓一小片地方（比如一个小区），两次请求之间歇半秒，别一次扫全城，更别商用。
> 大范围要用自己申请的钥匙，并遵守腾讯位置服务的使用条款。

相关笔记：`non-standard-xyz-and-gcj02`（瓦片和火星坐标）、`xyzTilesFormat`、`Google_tiles`。

## 0. 先搞懂三件事（2 分钟）

### 0.1 地图是“拼图”拼出来的

你手机上看到的地图不是一张大图，而是很多**256×256像素的小方块**拼成的，
行话叫“瓦片”。你拖动地图时，浏览器一块一块地下载小方块拼好给你看。

每块小方块有个编号：`z_x_y`。

- `z` 是放大级别：数字越大看得越细。**看楼块一般用 18 级**（能看清每栋楼）。
- `x, y` 是行列号：世界被切成 $2^z \times 2^z$ 块，18 级就是 26 万 × 26 万块。

### 0.2 楼块不是图片，是“图纸”

腾讯的楼块不是画好的图片，而是一份**图纸数据**发到你浏览器，
浏览器照着图纸现场盖出白色小楼。图纸里每栋楼就两样东西：

1. **底面轮廓**：楼在地面上的形状（一圈坐标点）。
2. **高度**：楼有多高（米）。

我们要抄的，就是这两样。

### 0.3 存下来的文件长什么样

最后存成一个叫 **GeoJSON** 的文本文件，里面一条条记录：

```json
{"顶面形状": [...一圈经纬度...], "height_m": 12}
```

`height_m: 12` 就是楼高 12 米。任何 GIS 软件（QGIS、ArcGIS）都能直接打开看。

## 1. 入口：为什么选腾讯的选点页面

目标网址：`https://lbs.qq.com/getPoint`（腾讯官方的坐标拾取小工具）。

选它有三个好处，都是大白话：

1. **不用登录、不用自己申请钥匙**：打开就能拖地图，随便看。
2. **它自带一把公用钥匙**：网页源代码里藏着一把官方演示钥匙
   （`key=NQQBZ-…`），浏览器用这把钥匙去要数据，腾讯认得就放行。
   我们跟着浏览器沾光，不用暴露自己的钥匙。
3. **它显示的内容最全**：放大到 18 级就有楼块，数据最完整。

小知识：老版本的选点页地址已经打不开了（404），现在这个是新版，不影响，照着做就行。

## 2. 动手第一步：打开 F12，找到数据的“送货单”

这一步的目标：亲眼看到浏览器向哪里要楼块数据。跟着做：

1. 用 Chrome 打开 `https://lbs.qq.com/getPoint`。
2. 按键盘上的 **F12**，顶部点 **Network（网络）**，再点下面的 **Fetch/XHR**。
   （这一步是让浏览器把“它向服务器要了哪些东西”列出来给你看。）
3. 在页面搜索框搜“镇远古城”或直接把地图拖到镇远（贵州，`108.429,27.053`），
   把地图**放大到 18 级**（右下角有比例尺，放到能看清每栋小楼）。
4. 上方过滤框输入 `tile`，你会看到一行请求（另一行 `rumt-zh.com` 是统计上报，不用管）：
  ```
  https://rt3.map.gtimg.com/tile?styleid=0&tiles=18_213618_148627,...&version=2268&building=1&style=100&compress=1&mapType=hybrid
  ```

**你可能会问的三个问题：**

- **问：我搜 `vector/pbf/mvt` 怎么什么都没有？**
  答：太正常了。腾讯没用公开标准格式，矢量数据就藏在这个叫 `tile` 的接口里，
  它穿着栅格瓦片的“马甲”，所以搜那些关键词搜不到。你已经找对了。
- **问：`building=1` 是什么？**
  答：可以理解成“顺便把楼块图纸也带上”的开关。有它才有楼，没它只有路面。
- **问：`tiles=18_213618_148627,...` 是什么？**
  答：就是“一次要 4 块拼图”的意思。`18` 是放大级别，后面是 4 块拼图的编号，
  浏览器为了省事一次要 4 块（2×2）。我们后面写程序也一次要 4 块，学浏览器的样子。

## 3. 编号有个坑：y 要“倒过来”

拼图编号里有个小陷阱，值得单独说，因为第一次做的人几乎都会踩。

全世界有两种数行号的方法：一种从**北极**往南数（叫 XYZ，谷歌用的），
一种从**南极**往北数（叫 TMS，腾讯用的）。同一块拼图，两种 numbering 差一个翻转：

$$
y_{\text{腾讯}} = 2^{z} - 1 - y_{\text{谷歌}}
$$

18 级时 $2^{18} - 1 = 262143$。举个真实例子：

- 镇远古城中心 `108.429, 27.053`，按谷歌算法算是第 `(210027, 110597)` 块。
- 但发给腾讯要写成 `18_210027_151546`，因为：

$$
262143 - 110597 = 151546
$$

- 如果你忘了翻转、直接发 `110597`，服务器会给你南半球大海的数据——一片空白，
  别怀疑人生，回来检查这一步就行。

程序里这行代码干的就是翻转，别删：
```js
// TMS y = N-1-xyz_y
```

多说一句：经纬度怎么算出块号（程序第一步干的就是这个，公式抄就行，不用背）：

$$
x = \left\lfloor \frac{lon+180}{360} \cdot 2^z \right\rfloor
$$

$$
y = \left\lfloor \left(1 - \frac{\ln\left(\tan\left(lat \cdot \pi/180\right) + \sec\left(lat \cdot \pi/180\right)\right)}{\pi}\right) \cdot 2^{z-1} \right\rfloor
$$

算出来的是谷歌编号 $(x, y)$，发给腾讯前记得按上面的翻转公式换成腾讯编号。

## 4. 服务器回了什么：一个“上了锁的箱子”

点开那行 `tile` 请求，看 **Response（响应）**，你会看到类似这样的东西：

```json
{"datas":[{"data":"J4eqHLWdTu3jwlNyjXQX..."},{"data":"..."}]}
```

解读：

- `datas` 里有 4 个元素，正好对应你一次要的 4 块拼图，一一对应。
- 每个 `data` 是一大串乱码（base64，一种把二进制转成文本的打包方式）。
- 把乱码解开，里面**还不是明文**——腾讯又加了一道自己的小锁（每个字节转两圈再异或）。
  这就是下面要讲的解码。

如果你只要 1 块（单块接口），返回的是 `{"data":"..."}` 单体，程序两种都兼容。

---

## 5. 开锁：解码其实就四步（不用怕，有现成代码）

“逆向”听起来吓人，其实过程很朴素：去翻浏览器用的说明书（`gljs` 那份约 4MB 的 JS），
找到它自己是怎么开锁的，原样抄下来就行。说明书里开锁函数叫 `decode`（编号 55722），
抄下来就是程序里的 `txDecode()`，四步：

1. **base64 解包**：把文本乱码还原成一串数字（字节）。
2. **开小锁**：每两个数字一组，转三圈、做一次异或——就是说明书里那两行数学式，
   照抄不用理解：
   ```js
   function rot(t,e){ return ((t>>8-e)&255)|((t<<e)&255); }
   ```
3. **拼成文字**：把数字按 UTF-8 规则拼成字符串。
4. **掐头去尾**：字符串尾巴有点填充，找到最后一个 `}` 掐掉。

开锁后得到的就是正常 JSON：

```json
{"ret":0, "features":[...], "pois":[...]}
```

`ret: 0` 表示“成功”。`features` 是图纸的正文，`pois` 是地名标注（比如“府城墙”），
`img` 是配图。我们只要 `features`。

> 拿镇远真数据验证过：一次 4 块约 98KB，解出 `27/18/120/97` 条记录，和浏览器显示一致。

## 6. 认楼：哪个编号是楼，高度藏在哪

`features` 里每条记录长这样（一条就是一栋楼或一条路或一个地名）：

```json
[196619, [33,227,27,7,-3,9,-26,-7], 4, ""]
  编号    底面形状（下面讲）        高  名
```

- **编号认楼**：腾讯给每类东西发了编号。说明书里写得明明白白，楼的编号是 **`196619`**。
  程序里就一行：`if(id !== 196619) continue;`——不是楼的统统跳过。
  （同家族还有几个相近编号，实测 `196619` 已覆盖全部楼块。）
- **高度就是第三个数，单位米**：上面这栋就是 4 米。镇远老城多是 `4/8/12` 米，
  大学校区能到 `100` 米。说明书里也是拿这个数乘个系数去盖楼，证实它就是米。
- **形状是“差分”记的**：`[33,227,27,7,-3,9,-26,-7]` 不是 4 个点，
  而是“第一个点是 (33,227)，后面每个数都是相对上一个点的偏移”。
  累加起来就是一圈：`(33,227) → (60,234) → (57,243) → (31,236)`，
  范围都在 0–256 之间（正好一块拼图 256 像素，单位是像素）。
- **偶尔看到 -47、305 这种出界数字别慌**：腾讯不把跨缝的楼切开，
  整栋归到一块里，边角自然会伸到邻居家。这是正常的，也是后面必须去重的原因。

---

## 7. 坐标：从像素到经纬度，再纠偏一次

现在手里是“某块拼图里的第几个像素”，要变成经纬度，分两步：

1. **像素 → 经纬度**：块号算出这块拼图在世界的位置，加上块内像素，
   套标准公式（slippy 公式，抄就行）→ 得到经纬度。注意：这是**火星坐标（GCJ-02）**，
   国家规定国内地图都要加偏，直接叠 GPS 会偏几百米。
2. **火星坐标 → 真实坐标（WGS-84）**：用公开的标准纠偏算法转一次。
   必须用完整版（含一堆 `sin` 的那个）。血泪教训：我第一版漏了 `sin` 项，
   只偏出几米还以为对了；补全后北京偏约 `500m`、镇远偏约 `400m` 才对。
   好消息：程序里已经内置了这一步（复用我 WebGIS-Dev 项目里的
   `coordTransform.js`，和 GitHub 上的 `wandergis/coordtransform` 同算法），
   输出的文件直接就是 WGS-84，进 QGIS/Cesium 不用再转。

## 8. 程序在干什么（一句话版 + 逐段版）

文件就一个：`qq_building_to_geojson.mjs`（要装免费的 Node.js 18 以上，双击装完就能用，无需其他依赖）。

**一句话**：你给个范围，它算出要哪些拼图，扮成浏览器一块块要回来、开锁、挑出楼、
转成经纬度（火星坐标→真实坐标一步到位，直接存 WGS-84）、去重、存文件。

**逐段对照**（打开文件能对上号）：

1. **看懂你要哪**：`--bbox 左,下,右,上` 四个数框个范围，
   或 `--center 经,纬 --delta 半径` 以某点为中心。**输入输出统一 WGS-84**：
   直接写 GPS、手持设备、奥维上的坐标就行，程序内部先转回火星坐标再算瓦片。
   程序算出覆盖了哪些拼图块。
2. **拼请求**：块按 2×2 一组，一次要 4 块，和浏览器一模一样。
   请求头带 `Referer: https://lbs.qq.com/getPoint/`（假装自己是从选点页来的）+ 浏览器 UA。
3. **慢慢要**：每批之间歇 400 毫秒，失败自动重试 3 次。别改小——太快会被服务器拉黑。
4. **开锁挑楼**：`txDecode` 开锁 → 只要编号 `196619` → 差分坐标累加 → 转经纬度
   → 再经 `gcj02ToWgs84` 转成真实坐标（代码直接复用我 WebGIS-Dev 项目里的
   `coordTransform.js`，和 GitHub 的 `wandergis/coordtransform` 同算法，已逐位验过一致）。
   输入输出统一 WGS-84：你只管给真实坐标，火星坐标只活在程序内部。
5. **去重**（最关键的一步！）：跨缝的楼会被相邻几块重复送来（一字不差），
   按“形状+高度”判重。实测镇远 `2189→1318`、开封金明校区 `2776→1520`，
   约 40% 是重复。不去重的话，相同的楼叠在一起，后面做 3D 会闪烁、破面。
6. **存文件**：`FeatureCollection`，顶层标了 `crs: WGS84`，
   每栋楼只有两个属性：`height_m`（楼高米数）+ `tile`（来自哪块拼图，方便排错）。
   拿到就能直接拖进 QGIS/Cesium，不用再转坐标。

**复制粘贴就能跑**（Node.js 18 以上，不用装任何依赖）：

## 9. 和一份“标准答案”的对比（告诉你差在哪）

群友之前用 C# 程序产出过一份镇远 3D Tiles（带 LOD 四叉树、约 381 个分块），
我把它当标准答案抽查对比过，结论如下：

| 比什么 | 标准答案 | 我们 | 说明 |
|---|---|---|---|
| 楼的位置 | — | 对齐 | 同一片抽查重合，没偏 |
| 每栋的身份 | `id/height` | 已对成 `id/height(+tile)` | 后面点选楼栋通用 |
| 楼高 | `3.77/7.52/11.28…` | `4/8/12…` | 恒定差约 0.94，疑似对方做了贴地形改正；我没擅自改，等你确认 |
| 同框数量 | 约 960 栋 | 1318 栋 | 口径和数据新旧差异 |
| 切块方式 | LOD 四叉树 | 按 18 级瓦片平铺 | 小范围看不出区别，整县才需要四叉树 |

转 3D Tiles 请用现成工具（如 CesiumLab 等），把 GeoJSON 喂进去就行，不用自己写。

## 10. 拿到 GeoJSON 之后：用第三方工具转 3D Tiles

本文到 GeoJSON 为止，后面不造轮子，直接用现成工具把楼“盖”起来，思路三步：

1. **指定高度属性**：每栋楼的 `height_m` 就是楼高（米），转换时选它做挤出高度。
2. **转换格式**：用第三方工具（如 CesiumLab、FME 等）把 GeoJSON 转成 3D Tiles
  （得到 `tileset.json + 一堆 .b3dm`），坐标已经是 WGS-84，直接用就行。
3. **加载到 Cesium**：把输出文件夹用 http 服务发布（不能双击文件直接打开），
   在 Cesium 里加载 `tileset.json` 并飞过去，点选楼栋还能读到高度属性。

## 12. 高德篇：同一套思路，换了三处机关

高德 `lbs.amap.com` 的 3D 演示页同样免登录有楼看，逆向链路和腾讯同构，
只是具体接口全换了。结论先行：**镇远同区域跑通 2510 栋**， heights 同样是整数米，
部分楼还带名称（腾讯没有）。

<p>
  <a href="../resources/amap-building-reverse/amap_building_to_geojson.mjs" download style="font-weight: bold; font-size: 1.1em;">📥 点击下载 amap_building_to_geojson.mjs</a>
</p>

```bash
node amap_building_to_geojson.mjs --bbox 108.415669,27.048246,108.433691,27.061264 --zoom 14 --out zhenyuan_amap.geojson
```

和腾讯版的三处不同（都是实测踩出来的）：

1. **认证多一步**：先 `GET web/init?key=` 拿 `tileVersion`（目前 `26_09_22_00`），
   再 `POST web_map/get_tile` 换 `tile_urls`（每次带新鲜 `auth_key`，会过期，
   所以每次运行现换现用）。演示 key 和腾讯一样是公开的，但它**绑域名白名单**：
   Node 里自带 `Referer` 能过，浏览器里会发你自己网站的域名，用演示 key 会直接
   `INVALID_USER_DOMAIN`——前端直连必须换自己申请的 key（白名单含自己域名），
   或走同源后端中转。
2. **数据是标准 protobuf**（不是腾讯的自创混淆）：`帧长+gzip+protobuf`，
   楼在 `type=3` 层，`polygon` 是 zigzag 打包差分，高度就是 `mainBuildingHeight`
   （米，整数）。`--zoom` 是**数据级别**（默认 14，和官方演示一致），
   不是显示级别。
3. **格网 y 是等距纬度行**：`x` 同标准 slippy，`y = (90-lat)×2^z/180`，
   不是墨卡托行号（用错会跑到南半球，顺带触发 `OVERSEA_FORBIDDEN`，
   别被这个报错骗了，先查 y）。某省瓦片偶发要 `access_oversea=1`，
   程序里已自动切换重试。

前端直跑版（Vue 直接 import，复用项目内 `coordTransform`）：
`WebGIS-Dev/frontend/src/domains/common/data-import/parsers/amapBuildingFetcher.js`，
用法和腾讯那版 `tencentBuildingFetcher.js` 对称（`fetchAmapBuildings` + `downloadGeoJSON`，
支持进度条与取消，记得传自己 key）。

关于楼名如实说：协议里确实有名字字段（`nameZh/nameEng`），解析器也写好了——
有就写 `properties.name`。但实测北京国贸 777 栋、陆家嘴 953 栋、西直门 433 栋、
镇远 2510 栋，名字**全是空的**（连 `multi_lang=1` 要来的字节都和原来一模一样）。
所以镇远文件里没有 `name` 不是漏解析，是源数据就没给；以后在别的区域抓到带名的楼，
会自动写进去，真要名字还是得拿 POI/AOI 去挂接。

**完整性质检**（同框对比腾讯）：腾讯 1318 栋里 77% 能在高德 15 米内找到对应；
放宽到 25/40/60 米后命中率 90%/96%/98%，且无系统偏移——说明两家是**同一批楼、轮廓画法不同**
（重心差十几二十米），剩下约 2% 属数据新旧差异。结论：程序没有漏数据，
看着“缺”多半是两家底库本来就不一样；要最全就把两家结果合并去重。

## 13. 翻车速查表（先看这里）
