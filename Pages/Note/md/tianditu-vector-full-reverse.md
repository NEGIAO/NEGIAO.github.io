## 1. 最终程序用法（范围＋图层选项＋级别→干净GeoJSON）

```bash
node tdt_vector_fetch.mjs --bbox 114.295,34.820,114.315,34.835 --zoom 16 --layers all --outdir ./out
node tdt_vector_fetch.mjs --center 114.305,34.827 --delta 0.004 --zoom 16 --layers CE,BK,BM --outdir ./out
```

- `--bbox`/`--center`：范围（WGS-84；CGCS2000≈WGS84直出无纠偏）；
- `--layers`：`all` 或逗号指定图层码（`BI,BV,CE,CK,BM,BK,AA,AB,AP,AD,AM,respt`）；
- `--zoom`：级别（15~18已验证）；`--outdir`：每层`<LAYER>.geojson`＋`merge_stats.json`＋`run_info.json`；
- `--tk`（默认demo）、`--delay`（默认400ms禁调小）、`--max-tiles`（默认500，超限拒绝请缩小范围/分片）；
- 内置 `--selftest`（裁剪/合并/去重合成用例，7项不过不发版）。
- 旧版中间工具（`tdt_full_dump.mjs` 纯采样、`tdt_merge_tiles.mjs` CE合并）功能已全并入最终程序，
  仓库已清理，勿再引用。

请求与建筑篇一致：

```text
https://tile{(x+y)%3}.tianditu.gov.cn/vts?t=vt&pk=<pkEncode(x,y,z)>&tk=<tk>&v=1.0
Referer: https://map.tianditu.gov.cn/
User-Agent: Mozilla/5.0 ... Chrome/126.0 ...
```

程序行为：

```text
bbox/center → 瓦片列表（超 --max-tiles 直接拒绝，请分片；单zoom）
→ 逐瓦fetch（间隔400ms，重试3次，失败记failures不伪造空瓦片）
→ 全量解析（三编码＋整数族＋ClosePath修复＋洞嵌套）
→ 通用拓扑（分层规则见§7：BV直出/CE-AP按id合/CK-BM按S8合/点线裁剪去重/残余打标）
→ <LAYER>.geojson（WGS84干净矢量）＋ merge_stats.json（分层in/out/union/fused/dedup）
```

建议采样矩阵（小范围、多种地貌各取 1~4 瓦片即可，不要大范围掃）：

| 区域类型 | 目的 |
|---|---|
| 城区密集建筑 | CE/respt/AA/CK 基线 |
| 主干道/路口 | AA 道路编码（Z5路名/X3/JF/D3 枚举） |
| 河流水系/绿地 | 找 CK/BM 之外的覆盖层（S8 取值枚举） |
| 行政边界附近 | BV 面 + BI 点（POI/单位） |
| z15/16/17/18 同框 | LOD 差异（各级别不是简单缩放，码系随级别变，见§5） |

出现新的图层名、新的 keys、新的 S8/QQ/X3 取值即新发现，按§6格式上报。

## 2. VTS 通用结构（全图层共用）

```text
文件 = 5字节头 + body
body = [裸层块（可选，无0x1a外壳）] + 若干标准图层（0x1a开头） + （无剩余间隙为正常）
```

三种层编码（z17随机10片已证实缺一不可，少一种即丢数据）：

| 编码 | 形态 | 例 |
|---|---|---|
| 标准层 | `0x1a + len + content{f1,f2,f3,f4,f5=4096,f15=2}` | AA/CE/CK/BM/respt/部分BI/BV |
| 前导层 | `raw[0]=0x1a + XOR长度 + XOR感知单要素` | 小瓦BK/BI/BV（如粹庭湖线、软件学院点） |
| 裸层 | body头部到首个标准层之间，无外壳，版式`[要素区][f2层名][f3 values][f4 keys](f5/f15可选)`，要素区首个为散装三元组、其余f1包裹 | 密集瓦多要素BI（19KB大瓦6个POI：万丰超市/夷山社区居委会/…） |

判定优先级：裸层（严格完整消费+f5/f15+合法层名+有效要素，强证据）>
前导（XOR模糊，弱证据）；同名同时命中只留裸层（超集去重）。
`gaps.bytes` 为未被标准层覆盖字节数；正常即裸层/前导长度，不再是“未知暗区”。

图层检测（严格，避免把任意字节误判成图层）：

```text
扫描每个 0x1a → 读 tag+len → content 必须完整消费（parseTop ok）
→ 且含 f5(extent) + f15(version) → 才算一个图层
```

| 字段 | 含义 | 备注 |
|---|---|---|
| f1 | features（repeated） | 与标准MVT错位 |
| f2 | layer名（图层代码字符串） | 12码：BI/BV/CE/CK/BM/BK/AA/AB/AP/AD/AM/respt |
| f3 | values（repeated Value） | 字符串/浮点 |
| f4 | keys（repeated string） | 属性名表 |
| f5 | extent（=4096） | 名义范围 |
| f15 | version（=2） | 版本 |

Feature：

| 字段 | 含义 |
|---|---|
| f1 | 几何容器（命令流；个别深嵌套 f1{f1{…}} 需递归 findCommands） |
| f2 | 几何类型：1=线，2=面，4=点（与标准MVT编号不同） |
| f3 | tags（packed uint32，[keyIdx,valIdx,…] → keys/values显式映射） |

XOR（先还原再解析，否则tags错位静默丢数据）：

```js
if (raw.length > 99) raw[99] ^= 0xff;
const body = raw.slice(5);
```

Value（MVT Value子集，`tdt_vector_fetch.mjs::parseValue`）：

| 编码 | 含义 | 例 |
|---|---|---|
| f1 wt2 | string（UTF-8） | 路名、楼号、区划名 |
| f3 wt5 | float32 LE | 建筑高度 h |
| f3 wt1 | float64 | 罕见，保留 |
| f4/f5/f6 wt0 | int64/uint64/sint64-zigzag（MVT整数族） | **AP.objectid**即f6 sint64（如`30 bc9423`→288030）；缺这支会把objectid解成null |
| f7 wt0 | bool | 暂未见实例，保留分支 |
| 非法UTF-8 | raw_hex | 说明XOR/切分有问题，先查还原步骤，不直接丢 |

几何命令流：`MoveTo=2 / LineTo=3 / ClosePath=7`，`count=整数>>>3`，
参数 zigzag 差分累加；名义 extent 4096，实际 buffer `[-82,4178]`（越界即误读；
全量dump用宽界 `[-1000,5100]` 做误读判定，建筑合并仍用核心 `[0,4096]` 裁剪）。
部分合法面没有 ClosePath，输出阶段再闭合，不要以 ClosePath 为保留条件。

> ClosePath陷阱（16_53576_25998 BM#2 634点环丢失案，三处同根已修）：
> ClosePath命令字恒为15（`count=15>>>3=1`）但**不占参数**；沿用命令计数的解析器
> 若不清零，会把下条命令误读成坐标，导致整要素丢弃（本瓦1BM+2CK共3要素中招；
> 建筑侧同输入验证外滩框135→139栋，+4/-0，新增4栋高度=层数×3全自洽）。
> 修法：ClosePath清计数；已有闭合环后遇渣则保留既有环并标 `_geom_partial=1`，
> 无闭合环仍整体拒绝（防错位误收）。面洞按包含关系嵌套为带洞Polygon输出
> （BM 634点主环内44735洞、CK 71点洞已验证），不依赖绕向。
> 同根三处（全量工具/前端fetcher/Node建筑脚本）已同步修；建筑脚本同输入验证
> 外滩框135→139栋（+4/-0，新增4栋高度=层数×3全自洽），输出schema不变。

坐标（CGCS2000≈WGS84，直接输出，无需纠偏；与腾讯/高德必须GCJ02往返不同）：

```text
lng = tx/n*360-180 + x/4096*(360/n)
lat = ss + (4096-y)/4096*(nn-ss)，其中 nn/ss 为该瓦片上下纬
```

## 3. 已确认图层清单（豫沪冀县域多地形、z15~z18共25+瓦实测，12层）

| 图层 | 几何 | 含义 | 关键字段 |
|---|---|---|---|
| BI | Point(4) | POI/单位点（单/多要素，前导/裸层/标准） | S8类型码、M2、P5、W2、Z5名称、B1区划码、F5 POI id |
| BV | Polygon(2) | 行政区画面（级别随上下文：省/市） | Z5名称（如“河南省”/“上海市”） |
| CE | Polygon(2) | 建筑面＋亭台构筑物＋村庄房群 | elemid(14位，410000豫/310000沪…)、A6、h高度、floor楼层、I8、Z5 |
| CK | Polygon(2) | 土地利用/绿地（官图对照确认方向） | S8（11/13/15，细分待图例） |
| BM | Polygon(2) | 水面（河湖渠池潭湾之面；BK注记落其内且S8配对） | S8（11/12/13/15/16） |
| BK | LineString(1) | 水系注记线（放水名，非水体；对标respt之于建筑） | S8（11/13/15/16）、Z5水名 |
| AA | LineString(1) | 道路线（码系随级别/区域变；J9=公路编号） | QQ(0/1/2/3)、A6、X3(01/02/04/0a/14/15)、Z5路名、V1、JF、D3、J9（z15/16，如S219） |
| AB | LineString(1) | 无名短线（支路/内部路候选；铁路已证伪） | X3、V1、D3 |
| AP | Polygon(2) | 区级行政区划面（跨zoom稳定+裁剪连续，高置信） | objectid（sint64整数） |
| AD | Point(4) | 地铁站＋出入口 | K0城码、A6（450101站/450190口）、C8、Z5站名、E0、L1、H7出口号 |
| AM | LineString(1) | 轨道交通线 | K0、C8、Z5线路名、C2线路号 |
| respt | Point(4) | 楼号标注点（仅z17/18） | elemid、lzh楼号（全角数字） |

注意：

- 不同瓦片图层集合不同（如 103995 瓦片无 BI/BM，有 BV/CE/CK/AA/respt）。
   absence ≠ 解析器丢数据，先查 `run_info.json` 的 layers 列表与
   `merge_stats.json` 的分层计数，再对照 §5 级别规则。
- CK 与 BM 在现有样本 keys/值完全相同（S8="11"），是同一分类的不同瓦片
  还是不同覆盖类型，需要水系/绿地采样才能区分，不要硬猜。
- AA 无 Z5 的记录是无名路段（tags 缺该对），不是解析失败。

## 4. 逐图层属性详解

### 4.1 CE（建筑，建筑篇已定论，全量视角补充）

- 条件：`layer==CE && type==2`，`elemid` 为 14 位数字（如 `41000002088680`）。
- keys：`elemid、A6、h、floor`（z17新增 `I8、Z5`，见下）。
- 高度只有 fix32 一种，源头仅约 1/3 有；有层数必 `h=floor×3`（外滩122栋39带高度100%自洽已验证）。
  与官方三维/弹窗非同一管线，不可嫁接（跨源互认~15%已证伪）。
- elemid前缀分区：`410000`豫（开封）、`310000`沪（上海外滩）、`410220`（开封县域高层）、
  跨省直接按前缀分区统计，不要混算。
- A6已见 `310200（乡村房群/果园/金龙口）/310300/310301（沪楼）/310500（金明高层）/310600/350205/350208`；
  上海楼Z5直接给楼名（`上海…花园/公司`），乡村房 `Z5=村名 + h=0 + 无floor`。
- 金明高层群（A6=310500，elemid 41022024…）：`h=105/35层、99/33、84/28、81/27`——
  30层级住宅，3倍律全成立（105=35×3），校区周边最高楼即此。
- z17新属性：亭台构筑物也进CE，如 `{"elemid":"41000002122945","A6":"350205","h":0,"Z5":"京友亭","I8":"无底座"}`。
  `h=0` + `I8无底座` + 有Z5名的多为非楼构筑物；只做楼体量统计时先滤 `h>0或floor非空`。
  跨瓦同elemid不同属性（如一瓦有I8一瓦无）以几何Union为准，属性取并集，不要当两个楼。
- 跨瓦：同 elemid 接缝才 Union（高/层禁做合并键）；残余重叠只打标 topo_review；
  跨瓦同楼异号记 dup_ids。详见建筑篇 §7。

### 4.2 respt（标注挂接层）

- keys：`elemid、lzh`（兼容 `name/label/title/Z5`，见建筑篇）。
- type=4 点，要素如 `{"elemid":"41000002088681","lzh":"５５号楼"}`。
- 流程：`读respt → elemid→文字 → 挂接到CE → properties.name`；空串/�过滤，无匹配不伪造。
- 全量视角：respt 是通用“注记按elemid挂接”模式的实例，后续 POI 名称层可复用该模式。

### 4.3 AA（线要素，道路）

- keys：`QQ、A6、X3、Z5、V1、JF、D3`（z15/16多 `J9`），type=1 开放路径。
- 样本（z17/18）：`{"QQ":"1","A6":"420400"/"440300","X3":"14","Z5":"文甫路"/"九章路"/"雪垠路","V1":"430503","JF":"0","D3":"5"}`。
- z15/z16码系不同：`QQ=0/2/3、A6=420201/440400/…、X3=01/02/04/0a，V1随A6走`，
  不再是430503常量——**AA码表随级别/区域变**，字典必须分级记录，不可拿z18码解读z15。
- `J9=公路编号`（高置信：金明z16单区61个J9全为`S219`，与郑尉路省道吻合；
  有J9的AA即挂编号干线，`X3=02+D3=2/JF=4` 组合多见于此）。
- 金明z16新值：`X3=15`（与QQ=2/A6=420400同条干线），AA无名段（缺Z5）多为干线复线/辅道。
- 解读（待多采样验证，不要当定论写死）：
  Z5=路名有无取决于该段是否挂名；A6疑似路段分类/区划相关码（420400/440300）；
  X3/JF/D3/V1/QQ 为线等级/方向/车道或内部分段码，需路口/跨瓦样本才能定。
- 跨瓦：同路分段，需按路名+编码接缝拼接（与 CE 的 elemid-Union 不同，不要复用同一合并键）。

### 4.4 CK（土地利用/绿地）/ BM（水面）

- keys：`S8`，type=2 面；已见 `11/13/15`（CK）与 `11/12/13/15/16`（BM）。
- 定性（用户官图对照＋坐标实证）：
  **BM=水面**：金明z16全部12条BK注记落入BM面且S8配对（11→11 ×8、13→13 ×3、16→16 ×2，
  12/12）；九曲河/先闻湖/雪垠湖/粹庭湖/光明湖/星光潭/月亮湾皆有归属面。
  **CK=土地利用/绿地**（用户对照确认方向；S8细分待图例）。
- S8语义（候选映射，置信分级）：
  BM侧 `16≈潭池水面`（中高：星光潭/月亮湾线面配对）、`15≈渠系水面`（中：两引水渠伴生；
  但柳池S8=15说明15亦含小池，15/16细分待图例）、`11≈河湖水面`（中高：8条注记归属）、
  `12/13≈水面子类`（中：光明湖→BM13；沪沪外滩BM待查）；
  CK侧 `11/13/15` 为利用/绿地子类（低，待图例＋靶瓦）。
  跨层注意：S8在BK（注记类型）、BM（水面类型）、CK（利用类型）、BI（POI类型）四处含义独立，
  不可串用；但BK↔BM的S8配对成立（注记与其水面同码）。
- 金明z16：CK94个（15瓦）、BM13个（7瓦）；无覆盖层的瓦多为纯道路/建筑瓦，无暗区。

### 4.5 BV（行政区划面）

- keys：`Z5`，type=2，常为瓦片全幅面（`(-82,4178)→(-82,-82)→(4178,-82)→(4178,4178)` 闭合）。
- 样本 `{"Z5":"河南省"}`（豫瓦）、`{"Z5":"上海市"}`（沪瓦）——级别随上下文（省/市）。
  不要当建筑/覆盖参与 Union；荒瓦可仅剩BV+AA（如北段738字节瓦）。

### 4.6 BI（点POI/单位，全量子集之首）

- keys：`S8、M2、P5、W2、Z5、B1、F5`，type=4；三种源都见过（前导/裸层/标准）。
- z17样本（11个POI）：`河南大学|土木建筑学院、国家教材|采购供应中心、万丰超市、`
  `夷山社区居委会、开封市金明|实验小学警务室、共享图书馆、前堌门、世纪星鼎立幼儿园`。
  `Z5` 常见 `A|B` 复合名（单位|下属），`|` 后半为具体点，不要截断。
- 乡村POI（z15断面）：`封丘康馨护理院、蒋楼村村委会、龙亭区果园小学、小李庄社区居委会、`
  `老君堂社区|居民委员会、太平庄、回回寨`——村委会/护理院/小学全进BI，乡村全覆盖。
- 校区POI（金明z16，框框住的证据）：`河南大学（S8=12/B1=160105）、河南大学|…药学院/统计学院、`
  `河南大学|…科研…、河南大学志…馆（图书馆）、河南大学|…苑`——院系楼馆全进BI（S8=12/13/14/15），
  B1新值 `180100/240100`。框对了，人全在。
- S8已见 `9/12/13/14/15`；M2已见 `160201/160301/170101/180101`（非空，大类码）；
  B1区划码已见 `120201/130105/130402/160101/160103/160104/160107/180304/190106/190107/190200/260112`；
  F5为POI id（10位数字）。
  空串字段保留（该要素该属性无值），不要删键。

### 4.7 BK（水系注记线，放水名的线）

- keys：`S8、Z5`，type=1 短线（2~43点），前导/裸层源；已见9水：
  `黄浦江（S8=11）、黄汴河（11，43点）、利汴河（13，40点）、九曲河（11，23点）、`
  `粹庭湖/先闻湖（11）、柳池（15，仅2点）、三姓庄引水渠（15）、柳池口总干渠（15）`。
- 定性（用户纠正＋坐标实证）：**BK不是水体，是水系注记**（对标respt之于建筑：
  respt按elemid给楼号，BK按位置给水名；2点短线不可能是水面几何，只能是注记）。
  金明z16验证：12条BK注记逐条落入BM水面，**S8两端配对**

- 用法：找水名走BK，找水面几何走BM（S8配对）；查水先查同框BK再追BM；
  z18某子瓦无BK属切分归属（落兄弟瓦），查水查同框四子瓦。

### 4.8 AB（无名短线段，铁路证伪，支路/内部路候选）

## 5. zoom 差异与缺数

- 可用级别 15~18（建筑脚本默认16较稳；全量采样建议15~18同框对比）。
- 各级别不是简单缩放：LOD、属性、源数据可能不同；z18 个别区域源数据缺失时，
  算法不能凭空补回（建筑篇已明确）。
- 已证实的级别相关（编制MVT/前端必须分支处理）：
  `respt` 只在 z17/z18 出现（z15/z16零respt）；

  `CE` 的 `I8/Z5` 在 z15 与 z17 均见、z18建筑瓦未见（样本有限，待补）。
- inventory 按 `z15/z16/z17/z18` 分组对比：某层在高级别消失先查源（同框低级别有无），再查解析。

## 6. 未知发现流程（gaps + 新keys）

- 每个瓦片 `gaps.bytes/ranges` 为未被**标准层**覆盖的字节统计；正常等于裸层/前导长度
  （49~504均为正常：小瓦49~131单要素前导，大瓦504多要素裸层BI）。
  真正的“未知发现”信号是：`bare=null && preamble=null` 却 gaps>0，或出现新图层名；
  此时先保留 raw.bin，再发 parsed.json。
- 中文差集法（已验证有效）：原始字节中文集合 − 解码值中文集合 = 隐藏数据；
  差集非空即解析不全（如本次7个POI名），为空则当批无漏网（水系面即属此列）。
- 新图层/新key 的上报格式：`图层名 + keys + 2~3个完整props样例 + 几何类型 + 所在瓦片号 + zoom`。
- 固定位置 XOR（raw[99]）是当前版本样本逆向结果，服务端升级后必须重验：
  症状为 CE 数量骤降、属性乱码、tags 长度奇数，直接按建筑篇 §3 重查。
