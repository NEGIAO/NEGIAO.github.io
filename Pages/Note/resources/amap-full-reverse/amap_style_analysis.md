# 高德矢量样式（style pbf/json）破解与解析对照

> 对象：`https://o4.amap.com/style/2.0.2.45/v1/pbf/1_0_s_migrate`（102,336 B）
> 同源可读版：`https://o4.amap.com/style/2.0.2.45/v1/json/1_0_s_migrate`（1.7 MB JSON，**直接给出字段名**）
> 实测对照：`amap_vector_fetch.mjs` 抓取的北京天安门 z12/z14 瓦片（poi/road/region/building/transit 五层）

## 1. 结论摘要

1. **这个 pbf 就是高德的渲染样式表**，不是瓦片数据：根消息 = `{f1: repeated 样式规则, f2: "2.0.2.45"}`，共 **7811 条规则**。
2. **同路径存在 JSON 版**（`/v1/json/` 而非 `/v1/pbf/`），内容与 pbf 一一对应（7811 条，字段名齐全），逆向 pbf 的可读性成本可直接绕过；pbf 只是同一份数据的紧凑编码。
3. **分类依据是 `mainKey` + `subKey` 两级码**，与瓦片要素里携带的 `mainKey/subKey` 完全同源：
   - `mainKey` 首位定图层：`1xxxx`=POI 注记、`2xxxx`=道路线、`3xxxx`=面状地物、`4xxxx`=引导注记、`55001`=建筑物；
   - `subKey` 是**组内**子类，必须与 mainKey 联合解释：`10001\|2`=红绿灯，而 `12024\|2`=景点/景观（见 §6）。
4. **样式块只有 5 种**：`poi`（2549 条）/`road`（4866）/`region`（354）/`building`（25）/`guide`（17）。颜色统一为 ARGB int32（如 `-10325622` = `#62718A`，alpha 255）。
5. **面类必须按补全后的键查色**（旧版判错，已修正）：`mainKey` 缺失的组补为 `30001` 后，`#D2E8F5` 那 320 个面实际是 `30001|3` = `#B4EBAF` **绿地**，不是建成区；栅格像素核验该桶 2280 样点中位色 `#D1E8AC`（绿）。`builtup` 桶已取消并入 `green`。
6. **瓦片里的 `mainKey/subKey` 会被编码端省略**（不是解析丢失）：`subKey` 缺省=1，`mainKey` 缺省=该层默认组（poi=12024 / region=30001 / building=55001），按此补全后实测要素 **主键 99.7%~100% 完整**，见 §11。
7. **已把这套映射接进解析器**：新增 `style_kind/style_class/style_conf/style_color/style_zoom`、`poi_class`、`region_class2` 字段，不改变原有字段与文件划分，缺映射文件时行为与旧版一致。

## 2. pbf 结构破解

### 2.1 外层

| 字段 | 线型 | 含义 | 证据 |
|---|---|---|---|
| `f1` | repeated msg | 一条样式规则 | 7811 条 |
| `f2` | string | 样式版本 `2.0.2.45` | 与 URL 路径一致 |

### 2.2 规则字段（与 JSON 字段一一对应）

| pbf 字段 | JSON 字段 | 说明 |
|---|---|---|
| `f1` | `mainKey` | 类别组 id（10 进制直存） |
| `f2` | `subKey` | 组内子类；**写在同组最后一条**（分组键后置） |
| `f3` / `f4` | `minZoom` / `maxZoom` | 可见级别区间（30 = 无上限） |
| `f5` | `poi{}` | POI 样式块 |
| `f6` | `road{}` | 道路样式块 |
| `f7` | `region{}` | 面样式块 |
| `f8` | `building{}` / `guide{}` | 建筑（55001）与引导注记（4xxxx） |
| `f10` / `f11` | — | 规则/续行标记（1） |

### 2.3 编码特点（为何不能逐字段硬解）

- **字段级增量**：与上一条相同的值直接省略。例：`mainKey=10001, subKey=2, z=17-18` 的规则只写了 zoom，`iconIndex=9/grid=128/H38` 出现在前一条，后一条只补 `H42/W42`。
- **子类键后置**：`subKey` 出现在该组**最后一条**规则上，前面的同组规则省略它（因此逐条读取会得到 `subKey=null`）。
- **区间可缺省**：缺失的 zoom 区间由相邻规则补齐。
- 直接解 pbf 需要复现上述三条规则；**因为同路径有 JSON，实际工程不建议再解 pbf**。

## 3. 样式 JSON 结构

```json
{"styles":[{"mainKey":10001,"subKey":1,"minZoom":10,"maxZoom":30,
  "poi":{"styleFontSize":11,"styleColor":-10325622,"styleTextStrokeColor":-1,
          "iconNameIndex":1,"iconIndex":108,"gridWidth":64,"gridHeight":64,
          "spriteWidth":512,"styleHeight":42,"styleWidth":42,"flags":0}}, ...],
 "version":"2.0.2.45"}
```

| 块 | 条数 | 字段 |
|---|---|---|
| `poi` | 2549 | styleFontSize、styleColor、styleTextStrokeColor、iconNameIndex、iconIndex、gridWidth/Height、spriteWidth、styleWidth/Height、flags、styleBackgroundIcon* |
| `road` | 4866 | lineType、lineStrokeType、fillColor、lineWidth、strokeWidth、strokeColor、fontSize、fontFillColor、fontStrokeColor |
| `region` | 354 | fillColor |
| `building` | 25 | roofColor、wallColor |
| `guide` | 17 | styleColor、styleFontSize、styleBackgroundIcon* |

**颜色规则**：int32 ARGB。`-10325622 & 0xFFFFFFFF = 0xFF62718A` → `#62718A`（不透明）；`#xxxxxx@0.xx` 表示带透明度。

**线宽规则**：z≤19 为像素值；z>19 按 2× 递增（z20=78 对应 z19=40），属于渲染端倍率，不是真实宽度。

## 5. 面状地物（region）分类

区域样式给的是 `(mainKey, subKey, zoom) → fillColor`。同一 `subKey` 在不同 `mainKey`/不同 zoom 段颜色不同，必须三者联合查。

按色相粗分（饱和度阈值 0.10/0.25）：

| 色例 | 判定 | 依据 |
|---|---|---|
| `#B2CEFE` `#80DFFF` `#82DCFA` | 水面 | 蓝相、饱和度 ≥0.25 |
| `#B4EBAF` `#B1F09E` `#AAED95` `#CFF7AE` | 绿地 | 绿相 70°–170° |
| `#D2E8F5` `#E4EEF5` `#EEEEEE` `#EDEEF0` | 地块底色（非绿地） | 蓝灰/灰、饱和度 <0.25 |

## 7. 与瓦片属性字段的对应

| 瓦片字段 | 含义 | 与样式的关系 |
|---|---|---|
| `mainKey` | 类别组 id | 直接查样式 `styles[mainKey]`；**可为空**（按层默认组） |
| `subKey` | 组内子类 | 道路分级 / POI 图标 / 面填色变体 |
| `resolution` | 坐标量化级 | 与样式无关，解码几何用（缺失时脚本回退 12 并打 `_resAssumed`） |
| `rank` | 同级排序 | 与样式无关 |
| `drawOrder` | 叠放次序 | 与 `region_top` 判定相关（>=80 顶层小面） |
| `uid` / `name*` | 要素 id / 名称 | 与样式无关；名称可用于校验分类 |
| `minZoom/maxZoom` | 要素可见区间 | 与样式的 zoom 段应一致（可用于交叉校验） |


## 8. 已落到解析器的改动

`amap_vector_fetch.mjs`：新增样式映射加载（同目录 `amap_style_class_map.json`，缺失则跳过），每个要素多出：

| 字段 | 含义 | 来源 |
|---|---|---|
| `style_kind` | 图层类型（poi/road/region/building/guide） | `mainKey` 前缀 |
| `style_class` | 类别中文名（高速路/国道/主干道/支路/建筑物…） | `mainKey` 映射 |
| `style_conf` | 判定置信度（高/中/低） | 映射表 |
| `style_color` | 该要素在该 zoom 的官方填充/线色 | `(mainKey,subKey,zoom)` |
| `style_zoom` | 该类别的可见级区间 | 样式 `minZoom/maxZoom` |
| `poi_class` | POI 类别（公共厕所/派出所/寺庙…） | `subKey` 映射（高频 34 类） |
| `region_class2` | 面类（水面/绿地/建成区/其他面） | 官方填色色相 + 饱和度 |

验证（天安门 z14，全 5 层）：建筑 2611 全带 `style_class=建筑物`；道路 1628 分为 巷道 1238 / 支路 105 / 次干 74…；`region_water` 24 全部 `region_class2=水面`、`#B2CEFE`。`--selftest` 27/27 通过。

## 11. 瓦片 mainKey/subKey 的编码与补全（复核结论）

样式按 `(mainKey, subKey)` 应用，所以每个要素都该有这两个键；但直接解码会看到大量 `mainKey=null` 或 `subKey` 缺失。逐字节复核后确认：**不是解析丢失，而是编码端按 protobuf「省略默认值」的方式做了省略**。

### 11.1 wire 结构

```
Layer{type=1..4}.f1 = repeated SameStyle
SameStyle{ f1: mainKey(uint32)  f2: subKey(uint32)  f3: resolution(uint32)  f4: repeated Item }
```

解码器的 `SAME` 规格已经把 f1/f2/f3 正确解出（9 瓦 / 76 图层实例 / 17281 要素审计：0 个空值、0 个 tag 越界、0 个 keys 未引用）；缺失就是 wire 上真的没有这个字段，不是读错。

### 11.2 补全规则与证据

| 规则 | 适用层 | 证据 |
|---|---|---|
| `subKey` 缺失 → **1** | 全部 | 样式表 7811 条里**不存在 subKey=0**；`20011`/`20019`/`20026` 等组全表只有 subKey=1，而这些组在瓦片里恰以「只有 mainKey」出现；363 个组样本按此补全后 **100%** 命中样式表 |
| `mainKey` 缺失 → **12024** | poi | 12024 是通用图标组（1442 个 subKey），覆盖实测 390 个图标 id 中的 389 个（99.7%） |
| `mainKey` 缺失 → **30001** | region | 30001 在任何瓦片里**从不明写**（=默认值）；其 `#B4EBAF` 绿 / `#B2CEFE` 蓝与栅格像素实测（`#D1E8AC` / `#ADD2FF`）一致；若按 30002 回退则颜色对不上 |
| `mainKey` 缺失 → **55001** | building | 样式表建筑组只有 55001 一个（25 条，subKey 1~26） |
| 不补，保留 null | road（少数组） | 这些组栅格像素出现 `#484848`/`#5591CE`/`#F6E3A3` 等跨族颜色，其中 `#484848` 在 7811 条规则里**不存在** → 属样式表未覆盖的线类，无法唯一归组，保留空值并打 `keySrc` |
