# 天地图矢量瓦片 GeoJSON 字段对照表

> 对象：`tdt_vector_fetch.mjs` 输出的 `<LAYER>.geojson` 属性字段。
> 本文与脚本内 `FIELD_DICT` 同源（脚本每次运行还会把该表写入输出目录的 `field_dictionary.json`）。

## 1. 为什么属性键用英文而不是中文

GeoJSON 本身允许中文键（UTF-8），但作为**数据交换格式**时英文键更稳，具体三条：

1. **落 Shapefile/DBF 会被截断或乱码**：DBF 字段名上限 10 字节，中文一个字符 2~3 字节，`数据包码` 直接超限；
   GDAL 会截成拼音或乱码，属性对不上。
2. **下游代码要写 `feature.properties.名称`**：JS/Python 里中文键虽能用，但点号访问、类型定义、SQL 建表都要引号包裹，
   跨语言（尤其 C++/Java GIS 组件）容易踩编码。
3. **字段名是 schema，不是标签**：你已发布文章里的表结构、历史输出、对比脚本都按 ASCII 键写死；改名即破坏兼容。

需要中文时用 `--zh-keys`（一次性开关，仅供人工查看/出图）：

```bash
node tdt_vector_fetch.mjs --center 114.3,34.8 --delta 0.004 --zoom 16 --layers BI,CE --zh-keys --outdir ./out_zh
```

输出示例：`{"名称":"国家能源局|河南监管办公室","POI分类码":"190108","POI编号":"1068621963","POI大类":"政府机构"}`

## 2. 字段总表（按字母序）

| 键 | 中文名 | 类型 | 含义 | 注意 | 实测出现图层 |

| `A0` | 标记8 | string | AU 低 zoom 线标记 | 含义未定 | （样本未出现） |

| `B1` | POI分类码 | string | 6 位 POI 分类，前 2 位为大类（17医院/15金融/19政府…） | 来自官方样式 icon 分支反推，非全表 | BI |
| `B7` | 地名 | string | 注记类文字：行政地名、河流名、山名、国名 | 注记层用 B7，POI 层用 Z5 | AF, BC, BN |
| `C2` | 线路号2 | string | AM 的线路编号（01=1号线） | — | AM |
| `C8` | 标记 | string | 地铁/构筑物标记（实测恒 1） | 含义未定 | AD, AM |
| `D3` | 道路等级 | string | 1~5，1 最高 | 与 X3 组合判断等级 | AA, AB |
| `E0` | 标记2 | string | AD 的状态标记（实测 0） | 含义未定 | AD |
| `E4` | 标记3 | string | AJ 的样式/分级码 | 含义未定 | AJ |
| `F5` | POI编号 | string | POI/地名点稳定 ID（10 位） | 跨瓦去重键 | BI, CA |

| `H7` | 出入口号 | string | 地铁出入口字母 A/B/C/D… | 与 L1+A6 组成出入口唯一键 | AD |
| `I8` | 类型码 | string | 各层分级/类型序号（如 CE 的“无底座”） | 语义按图层不同 | AF, CA |

| `M2` | 大类码 | string | BI 的 POI 大类码（160201/170101 等） | 与 B1 并存，含义相近，优先用 B1 | BI |

| `O4` | 地名等级 | string | 1首都 / 2市 / 4区县；" "=空 | AF 的 O4 可直接映射行政级别 | AF, AG, BC |
| `P5` | POI子类码 | string | 银行品牌等子类码（130001=工行） | 需与 B1=150101 联用 | BI |
| `QQ` | 道路标记2 | string | 1/2/3，z16+ 两个通用层按它开关 | 含义未定，勿当车道数 | AA |

| `_topo_review` | 拓扑待核 | number | 1=存在残余重叠/包含，几何未改 | 人工复核标记 | （样本未出现） |
| `display` | 显示开关 | string | 注记显示控制字段 | — | （样本未出现） |
| `elemid` | 要素ID | string | 建筑物稳定 ID（14 位数字或含字母方案） | CE/respt 靠它挂接；跨瓦会重复，需 Union | CE, respt |

| `h` | 高度 | number | 建筑高度，单位米 | 0=无高度/平房；3D 拉伸直接乘此值 | CE |

## 3. 派生字段与元数据字段

### 3.1 派生字段（脚本计算，非瓦片原始属性）

| 键 | 中文名 | 类型 | 由什么派生 | 说明 |
|---|---|---|---|---|
| `height_m` | 高度_米 | number | `h` | 与 `h` 同值；`h=0` 时不输出此键（无高度） |
| `floors` | 楼层数 | number | `floor`（字符串转数字） | 恒等于 `height_m/3` |
| `name` | 名称 | string | `CE.Z5`，缺失时按 `elemid` 从 `respt` 补 | z18 实测约 54% 建筑有名字 |

### 3.2 元数据字段（`_` 前缀，标识处理过程）

| 键 | 中文名 | 类型 | 取值含义 | 说明 |
|---|---|---|---|---|
| `_tile` | 来源瓦片 | string | `z_x_y` | 融合要素取首个片段所在瓦 |
| `_seam_merged` | 接缝已合并 | 1 | 1=跨瓦同 id 做过 Union | 无此键=未跨瓦合并 |
| `_fused_from` | 融合片数 | number | CK/BM 按 S8 并了几个环片 | >1 才是并出来的 |
| `_topo_review` | 拓扑待核 | 1 | 1=存在残余重叠/包含，几何未改 | 人工复核标记 |
| `_geom_partial` | 几何截断 | 1 | 1=源几何不完整（缺闭合环/命令流中断） | 源瓦片问题，不是解析失败 |
| `_poi_group` | POI大类 | string | B1 前两位映射的大类 | 粗分；细类看 `B1`/`P5` |

## 5. `--layers all` 各级别实际输出图层数（实测）

|---|---|---|

| z6 | 7 | `AF` `AG` `AR` `AW` `BC` `BV` `CC` |
| z10 | 8 | `AF` `AN` `BK` `BM` `BV` `CA` `CC` `CK` |
| z12 | 11 | `AA` `AF` `AM` `AP` `AX` `BA` `BI` `BK` `BM` `BV` `CK` |
| z16 | 13 | `AA` `AB` `AD` `AJ` `AM` `AP` `AX` `BI` `BK` `BM` `BV` `CE` `CK` |

样本并集：**34 个图层**（75 个已识别码中）；单次运行 7~17 个文件，取决于 zoom 与视域。

## 6. 解析完整性审计（9 瓦 / 76 图层实例 / 17281 要素）

| 检查项 | 结果 | 说明 |
|---|---|---|
| Value 子字段类型分布 | 字符串 3655、sint64 641、float32 58 | 三种类型全部有解析路径；已补标准 MVT `field2/float32` |
| 属性值为 null/未解析 | **0** | 无“解不出来的值” |
| tag 索引越界被丢 | **0** | 键值对索引全部在 `keys`/`values` 范围内 |
| 层内 `keys` 声明未被引用 | **0** | 声明的键全部被至少一个要素用到 |
| Layer 消息字段 | 仅 f1/f2/f3/f4/f5/f15 | 无被忽略的字段 |
| Feature 消息字段 | 仅 f1几何/f2类型/f3tags | 无 `id` 字段（稳定 ID 在属性里：`elemid`/`F5`/`objectid`） |

结论：**protobuf 层解析无丢失**；此前的“不完整”发生在输出阶段的白名单——CE 只留 4 个键、CK/BM 只留 `S8`、AP 只留 `objectid`。
现已改为：**原始键全部保留 + 追加派生键**。

## 7. 已知边界（无法从瓦片得到的）

1. `S8` 子类的中文含义：官方样式对同层所有 S8 同色，无图例；需按已知地物空间取样标定。
2. `X3/D3/JF/QQ/JP` 等分级码的确切语义：只能给出“码值→线宽/配色”的映射，没有中文等级名。
3. 非标准编码层（前导层/裸层）只取 f1/f2/f3 三个字段：实测这些层的属性与标准层一致，但若官方新增字段，需同步扩展。
